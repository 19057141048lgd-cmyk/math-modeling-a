## 0. 算法概览

### 0.1 角色与目标

本算法把"将一个计算图调度到 SIMD AI Core 上" 这件事拆成三步。它**不是**具体优化策略，而是一条**确定性的输入→输出管线**，每一步的输入是上一步的输出，决策完全由本步内的规则决定，不依赖外部经验数据。整套算法跑完得到：

- 一条**调度序列**：原图节点 + 必要时插入的 SPILL 节点
- 一组**换出/换入记录**：每次换入换出的 tensor 编号、字节数、来源 op、目标 op
- （由步骤 3 给出）每节点的**起始时间**和**结束时间**

三步关系：

```
        ┌─────────────────────────────────┐
        │ 步骤 1: 反向 DFS 拓扑排序        │
        │  (求一条"驻留峰值尽量小"的拓扑序) │
        └────────────────┬────────────────┘
                         │ 访问顺序 seq
                         ▼
        ┌─────────────────────────────────┐
        │ 步骤 2: 缓存换入换出插入          │
        │  (按 seq 模拟驻留,溢出时插 SPILL) │
        └────────────────┬────────────────┘
                         │ 扩展图 G' = (V∪V_spill, E∪E_spill)
                         ▼
        ┌─────────────────────────────────┐
        │ 步骤 3: 依赖就绪 + pipe 流水排布   │
        │  (无内存状态,算 start_time/end_time)│
        └────────────────┬────────────────┘
                         │ 调度时间表
                         ▼
                  总执行时间 = max(end_time)
```

### 0.2 输入格式

算法接受两种格式输入。两种格式在算法内部统一抽象为"Op 节点 + Tensor 缓冲区"两类实体。

#### 格式 A：显式 ALLOC / FREE

```
Nodes: [
  { Id, Op, Pipe, Cycles, Bufs },     // 计算/搬运 Op
  { Id, Op, BufId, Size, Type },      // Op=ALLOC 时无 Pipe/Cycles/Bufs
  { Id, Op, BufId },                  // Op=FREE 时无 Pipe/Cycles/Bufs/Size/Type
  ...
]
Edges: [ [StartNodeId, EndNodeId], ... ]
```

ALLOC / FREE 节点显式存在，分别标记一个 BufId 的生命周期起止。

#### 格式 B：二部图格式（评测用例使用的格式）

```
tensors: [ { id, pos, size } ]      // pos ∈ { DDR, L1, UB }  id ≥ 10001
ops:     [ { id, op, pipe, cycles } ] // op ∈ { COPY_IN, COPY_OUT, MATMUL, ... }  id ≥ 1
edges:   [ { source, target, data_size } ]
```

格式 B 没有 ALLOC / FREE。算法在内部按"tensor 第一次被 op 涉及 = 申请，最后一次被 op 涉及 = 释放" 推算生命周期，**等价于**隐式插入 ALLOC / FREE 节点（但仅在需要 SPILL 时才显式插入 COPY_IN / COPY_OUT 节点）。

`pipe` 字段取值属于 `PIPE_MTE2`、`PIPE_MTE3`、`PIPE_M`、`PIPE_V` 之一，调度与仿真均直接读取该字段，不按 `op` 名称推断 Pipe。

> **id 空间冲突**：格式 B 中 op id 与 tensor id 范围不重叠（op 1~N, tensor 10001~），但**算法内部**统一使用 `o{op_id}` / `t{tensor_id}` 命名空间，避免 id 串味。新增 SPILL 节点 id 从 max(op_id, tensor_id)+1 起递增。

### 0.3 输出格式

```
调度序列:  [n1, n2, n3, ...]      // 节点 Id 列表，含原节点 + 必要时插入的 SPILL 节点
SPILL 表:  [ { spill_out_id, spill_in_id, tid, pos, size, ... } ]
时间表:    { nodeId: { start, end } }    // 由步骤 3 给出
```

每个 SPILL 记录在序列里对应具体节点：首次写回 DDR 时为 `COPY_OUT` + `COPY_IN` 两个节点，复用已有 backing 时只有 `COPY_IN`。

### 0.4 与题目 1 / 2 / 3 的对应

| 题目 | 对应步骤 | 说明 |
|------|------|------|
| 题目 1（核内存储峰值） | 步骤 1 + 步骤 2 的模拟部分 | 步骤 1 给出拓扑访问顺序，步骤 2 的模拟给出该顺序下每种存储类型的驻留峰值 |
| 题目 2（换入换出方案） | 步骤 2 整体 | 在题目 1 的顺序上做溢出检测与 SPILL 插入，给出换入换出方案与新增搬运量 |
| 题目 3（流水排布） | 步骤 3 | 在题目 2 的扩展图上做乱序流水排布，最小化总执行时间 |

### 0.5 op-tensor 二部图与 op-op 邻接表

二部图格式的边是 `op → tensor` 或 `tensor → op`，op 节点不直接相邻，依赖通过 tensor 桥接。例如 `op1 → T1 → op2` 是两条边（`op1, T1` 与 `T1, op2`）。格式 A 的图已是 op-op 直接邻接。

> **本算法的步骤 1 基于 op-op 邻接表工作**。当输入为二部图时，步骤 1 的"首先" 阶段会完成 `op-tensor → op-op` 的桥接转换，并同时保留原二部图引用（含 `tensors` 字段与原始 `edges` 列表）—— 步骤 2 的"按 tensor 生命周期扫描" 直接使用原二部图，不重新桥接。桥接规则与伪代码见 1.3 节。

## 1. 步骤 1：多源 reverse DFS 拓扑排序

### 1.1 形式化定义

设 DAG $G = (V, E)$（$V$ 为 op 节点集，$|V| = $ op 节点数；输入为二部图时由 1.3 节"首先" 阶段桥接得到）。定义如下函数与集合：

- $\text{pred}(v) \triangleq \{u \in V \mid (u, v) \in E\}$
- $\text{succ}(v) \triangleq \{w \in V \mid (v, w) \in E\}$
- $V_{\text{in}} \triangleq \{v \in V \mid \text{pred}(v) = \varnothing\}$
- $V_{\text{out}} \triangleq \{v \in V \mid \text{succ}(v) = \varnothing\}$

**节点深度** $\text{depth}: V \to \mathbb{N}_0$：

$$
\text{depth}(v) = \begin{cases} 0, & v \in V_{\text{in}} \\ 1 + \max_{p \in \text{pred}(v)} \text{depth}(p), & \text{otherwise} \end{cases}
$$

**判定函数** $\text{is\_copy\_in}, \text{is\_copy\_out}: V \to \{0, 1\}$ 由 op 字段取值。

**排序 key 包含两种**（升序语义，详见 1.3 主循环）：

$$
\text{key}(p) = \big( \neg \text{is\_copy\_in}(p),\ \text{depth}(p),\ -\text{id}(p) \big) \quad \text{(主循环: 多前驱展开顺序)}
$$

$$
\text{start\_key}(p) = \big( \neg \text{is\_copy\_out}(p),\ \text{depth}(p),\ -\text{id}(p) \big) \quad \text{(起始: 多源压栈顺序)}
$$

> 两种 key 第一层不同：主循环 key 关注"数据晚搬运"，起始 key 关注"栈底 = seq 最后一个 = COPY_OUT"。

### 1.2 输出定义与不变量

算法输出**访问顺序** $\text{seq}: \{0, 1, \ldots, |V|-1\} \to V$，是双射，满足：

| 不变量 | 形式化 |
|--------|--------|
| 完整覆盖 | $\text{seq}$ 是 $V$ 的双射（即所有 op 都被访问） |
| 拓扑正确 | $\forall (u, v) \in E:\ \text{seq}^{-1}(u) < \text{seq}^{-1}(v)$ |
| 栈底不变量 | $\text{seq}(|V|-1) = \arg\min_{v \in V_{\text{out}}} \text{start\_key}(v)$（seq 最后一个是 $\text{start\_key}$ 最小的 out 节点；当 $V_{\text{out}}$ 包含 $\text{COPY\_OUT}$ 时, 该节点必为 $\text{COPY\_OUT}$） |
| 确定性 | 算法无随机无外部参数, 同输入必得同输出 |

### 1.3 算法

**首先, 二部图预处理与深度预计算**:

1. **二部图 → op-op 邻接表**（仅二部图情形）。按以下规则把 op-tensor 边桥接为 op-op 邻接：若 $\text{op}_{\text{src}} \to \tau$ 且 $\tau \to \text{op}_{\text{dst}}$（其中 $\tau$ 是 tensor），则建立 $\text{op}_{\text{src}} \to \text{op}_{\text{dst}}$ 的依赖边。

   ```text
   输入: 二部图 (V_op ∪ V_tensor, E_op_tensor)
   输出: op-op 邻接表 pred_map[op] / succ_map[op] (V_op = {op.id})
   副作用: 保留 graph_json 引用 (含 'tensors' 与原始 'edges') 供步骤 2 沿用

   for op in V_op:
       pred_map[op] = set()
       succ_map[op] = set()

   for edge in E_op_tensor:
       if edge = (op_src, tensor_t):
           # op_src 产出 tensor_t
           for edge2 in E_op_tensor where edge2.source == tensor_t and edge2.target in V_op:
               succ_map[op_src].add(edge2.target)        # op_src 是 op_dst 的前驱
       elif edge = (tensor_t, op_dst):
           # tensor_t 被 op_dst 消费
           for edge2 in E_op_tensor where edge2.target == tensor_t and edge2.source in V_op:
               pred_map[op_dst].add(edge2.source)        # op_src 是 op_dst 的前驱
   ```

   格式 A 的图已经是 op-op 直接邻接的，跳过此子步。

2. **深度预计算**。从 $V_{\text{in}}$ 起 BFS 推 $\text{depth}(v) = \max_{p \in \text{pred}(v)} \text{depth}(p) + 1$（in 节点 $\text{depth} = 0$），复杂度 $O(|V| + |E|)$。

**然后, 多源起始与主循环**（含前驱优先级排序, 算法核心）：

**多源起始**：令 $S \triangleq \text{sort}(V_{\text{out}},\ \text{by}=\text{start\_key},\ \text{asc})$，初始化栈 $\sigma \leftarrow S$（key 小的先入栈 → 栈底；key 大的后入栈 → 栈顶），$\text{visited} \leftarrow \varnothing$，$\text{seq} \leftarrow \varepsilon$。退化情形：若 $V_{\text{out}} = \varnothing$（环退化或孤立图），fallback 到 $\{v^*\}$ 其中 $v^* = \arg\min_v \text{id}(v)$。

**主循环**：

循环不变式: $|\text{seq}| = |\text{visited}|$, $\text{seq}$ 是 $\text{visited}$ 的双射, $\sigma$ 是当前未访问节点的"待处理栈"。

```
while σ ≠ ∅ ∨ visited ≠ V:
    if σ = ∅:                                          // 栈空 (多源全清空后, 处理剩余)
        R ← V \ visited
        if R = ∅: break
        Q ← sort(R, by = key, asc)                     // 剩余节点按主循环 key 升序
        σ ← σ ∘ Q                                       // key 小的先入栈 → 栈底

    u ← top(σ)                                          // 栈顶
    if u ∈ visited: σ ← pop(σ); continue               // 防御性去重

    P ← pred(u) \ visited                               // u 的未访问前驱
    if P ≠ ∅:
        apply_pred_priority_sort(P)                     // ★ 前驱优先级排序 ★
        σ ← σ ∘ Q_sorted
    else:
        visited ← visited ∪ {u}
        seq ← seq ∘ u                                    // u append 到 seq 末尾 (访问)
        σ ← pop(σ)
```

**前驱优先级排序 (本算法的核心步骤)**:

当 $u$ 有多个未访问前驱 $P = \text{pred}(u) \setminus \text{visited}$ 时, 决定这些前驱在 $\sigma$ 中的**压栈顺序**, 从而决定 $u$ 访问完毕后这些前驱的**访问顺序**。排序流程:

1. **定义 key 函数** (在 1.1 已给出):

   $$\text{key}(p) = \big( \neg \text{is\_copy\_in}(p),\ \text{depth}(p),\ -\text{id}(p) \big)$$

2. **按 key 升序排** $P$: $Q = \text{sort}(P,\ \text{by}=\text{key},\ \text{asc})$

3. **升序压栈**: 把 $Q$ 依次 append 到 $\sigma$ 末端, 即 $\sigma \leftarrow \sigma \circ Q$。

**为何"升序压栈 + LIFO 弹栈"等价于"按 key 降序访问"**:

- 升序排 $\Rightarrow$ key 最小的 $p_1$ 在 $Q$ 的**最前**, 在压栈时**最先入栈** $\Rightarrow$ 位于 $\sigma$ 的**最深**(底)
- 升序排 $\Rightarrow$ key 最大的 $p_k$ 在 $Q$ 的**最后**, 在压栈时**最后入栈** $\Rightarrow$ 位于 $\sigma$ 的**最浅**(顶)
- LIFO 弹栈 $\Rightarrow$ $p_k$ (key 最大) **先弹** $\Rightarrow$ **先访问**
- $p_1$ (key 最小) **后弹** $\Rightarrow$ **后访问**

即: $\text{key}(p) \text{ 越大} \Rightarrow p \text{ 越先访问} \Rightarrow p \text{ 越先在物理时间上执行}$。

**key 三层的设计意图**:

| 优先级 | key 维度 | key 升序规则 (小的先压栈 → 后访问) | 设计意图 |
|--------|----------|-----------------------------------|----------|
| 第一层 | $\neg \text{is\_copy\_in}$ | $\text{COPY\_IN}$ 在前 (key = 0) → 后访问 | 数据"只在需要时才搬运进来": $\text{COPY\_IN}$ 物理时间上**晚执行**, 产出的 tensor 驻留时间短 |
| 第二层 | $\text{depth}$ | 浅在前 (depth 小) → 后访问 | "小计算分支靠后处理": 浅节点生成的 tensor 生命周期短, 物理晚执行可压缩其生命 |
| 第三层 | $-\text{id}$ | id 大在前 ($-id$ 小) → 后访问 | 字典序靠前 → 物理时间上靠前执行: 同 depth 多前驱时按输入 Id 升序给访问顺序 |

**最后, 输出**: 返回 $\text{seq}$。

### 1.4 正确性证明 (概要)

**命题 1.1 (拓扑正确)**. $\forall (u, v) \in E: \text{seq}^{-1}(u) < \text{seq}^{-1}(v)$.

*证*: $u$ 只能在 $P = \text{pred}(u) = \varnothing \lor \text{pred}(u) \subseteq \text{visited}$ 时被 append 到 $\text{seq}$。后一种情况要求每个 $p \in \text{pred}(u)$ 已被访问, 而 $(u, v) \in E$ 意味着 $u \in \text{pred}(v)$, 因此 $v$ 的访问条件要求 $u$ 先访问. ∎

**命题 1.2 (完整覆盖)**. $\text{seq}$ 是 $V$ 的双射, $|\text{seq}| = |V|$.

*证*: 循环条件是 $\sigma \neq \varnothing \lor \text{visited} \neq V$. 每次 append $u$ 后 $\text{visited} \leftarrow \text{visited} \cup \{u\}$ (去重), $\sigma$ 同步减少, 总元素守恒. 终止时 $\text{visited} = V$, $\text{seq}$ 长 $|V|$. ∎

**命题 1.3 (栈底不变量)**. $\text{seq}(|V|-1) = \arg\min_{v \in V_{\text{out}}} \text{start\_key}(v)$.

*证*: 由 Step 1.A, $\arg\min \text{start\_key}$ 的 out 节点是 $\sigma$ 的**栈底**。主循环中后续所有压栈操作 ($\sigma \leftarrow \sigma \circ Q$) 都把新元素附加到栈顶, 栈底永远不变。LIFO 下栈底最后弹出, 也就是 $\text{seq}$ 的最后元素。∎

**命题 1.4 (确定性)**. 算法无随机数, 无外部参数, 所有 sort 均基于确定性 key。同输入必得同输出. ∎

## 2. 步骤 2：缓存换入换出插入

> **接口**：`step2_spill_insertion(graph_json, seq, capacity)`。`capacity` 由调用方从 `config.txt` 的 `[capacity]` 段读出后传入，本步骤不内置默认容量。
>
> 本步骤把每次 `COPY_IN` 的输出重命名为新的片上 tensor incarnation，并把本次换入后的全部消费者重连到该 tensor；同一 logical tensor 只建立一个持久 DDR backing，已建立 backing 后不再重复写回 DDR。

### 2.1 目标

给定：

- 步骤 1 输出的访问顺序 $\text{seq}$（按"访问即物理执行"语义）
- 每种 Type 的容量 $C_T$（来自 `config.txt`：L1=524288 字节、UB=131072 字节）
- 二部图原图（步骤 1 的"首先"阶段已保留 graph_json 引用）

输出：

- 扩展序列 $\text{seq}_{\text{ext}}$：$\text{seq}$ + 若干 `COPY_OUT` / `COPY_IN` 节点（**插在 op 与 op 之间**）
- 扩展图 $G' = (V \cup V_{\text{spill}},\, E \cup E_{\text{spill}})$
- SPILL 操作记录表

使得：**任意时刻、每种 Type 的驻留量 $\text{resid}_T(t) \le C_T$**。

> **关键简化**：算法**不分配具体地址**（offset），只跟踪"占用量"。

### 2.2 关键定义

#### 2.2.1 tensor 涉及序列（uses）与 next_use

对每个**非 DDR** tensor $\tau$（DDR tensor 不占片上容量，步骤 2 不处理），定义其**涉及序列**为按 seq 步序排序的 op 集合：

$$
\text{uses}(\tau) = \big[(\text{step}_1,\, \text{op}_1),\ (\text{step}_2,\, \text{op}_2),\ \ldots,\ (\text{step}_k,\, \text{op}_k)\big]
$$

约定 $\text{step}_1 < \ldots < \text{step}_k$，$\text{op}_1$ 是 $\tau$ 的生产 op，后续是消费 op（$k=1$ 即生产即消费，多见于 COPY_IN / COPY_OUT 的中间产物）。

模拟中维护 $\tau$ 的 **next_use 指针**：处理完第 $i$ 次 use 后，$\text{next\_use}(\tau, i) = \text{step}_{i+1}$（若 $i < k$），否则 $\varnothing$（$\tau$ 不再被使用，下一步释放）。next_use 给出 victim 选择时**未来最久不用**的判据（Belady 选 victim，见 2.4 (c)）。

#### 2.2.2 驻留量、活跃集与 use 处理

$$
\text{resid}_T(t) \;=\; \sum_{\tau \in \text{Active}_T(t)} \text{size}(\tau)
$$

- $T \in \{\text{L1}, \text{UB}\}$，每 Type 独立检测
- $\text{Active}^{alloc}_T(t)$：当前 op 的 COPY_IN 与输出均已申请、当前 op 的末次输入尚未释放时，所有驻留的 $T$-型 tensor；这是容量硬约束检查点
- $\text{Active}^{steady}_T(t)$：当前 op 执行完成并释放末次输入后的稳态集合
- $C_T$：Type $T$ 的硬件容量

约定 $\tau$ **alive iff** $\text{first}(\tau) \le t < \text{last}(\tau)$（半开，$\text{first} = \text{step}_1$, $\text{last} = \text{step}_k$）。use 处理按当前 use 索引 $i$（在 $\text{uses}(\tau)$ 中的位置）分支：

- $i = 1$（生产）：先加入 $\text{Active}_T$，$\text{next\_use} = \text{step}_2$（若 $k \ge 2$）或 $\varnothing$
- $1 < i < k$（中间 use）：更新 active 中 $\tau$ 的 $\text{next\_use} = \text{step}_{i+1}$
- $i = k$（末次 use）：容量检查时仍保留在 $\text{Active}^{alloc}_T$；当前 op 执行完成后才移除

每步在 alloc 完成、execute/free 之前检查 $\text{resid}^{alloc}_T(t) > C_T$，溢出则触发 2.4 (c) Belady 选 victim + SPILL 插入。SPILL 后再次断言 $\text{resid}^{alloc}_T(t) \le C_T$。

#### 2.2.3 SPILL 锚点（使用间隙）

选中 victim $\tau$ 后，SPILL 插在 $\tau$ 的**使用间隙**内（$\tau$ 在 $[\text{out\_after\_step}, \text{in\_before\_step}]$ 区间内不被任何 op 使用，外提到 DDR 不与活跃使用冲突）：

- $\text{out\_after\_step} = \text{step}_i$（已发生的最后一次 use 步）：`COPY_OUT` 节点插在 $\text{seq}[\text{step}_i]$ 之后（仅首次真实写回时存在）
- $\text{in\_before\_step} = \text{step}_{i+1}$（下一次 use 步）：`COPY_IN` 节点插在 $\text{seq}[\text{step}_{i+1}]$ 之前

> **物理态闭合**：SPILL 把 victim 移出 active 后，必须在 `in_before_step` 通过换入节点把它重新加回 active，否则 victim 的后续 use 找不到 active 项，驻留账目会失真。实现见 2.4 (a0)。

#### 2.2.4 持久 DDR backing 与 tensor 重命名

每个片上 tensor $\tau$ 最多建立一个持久 DDR backing，后续换入均从同一 backing 回拷：

| 情形 | COPY_OUT 节点 | DDR tensor | COPY_IN 输出 |
|------|------|------|------|
| $\tau$ 尚无 backing | 保留，真实写 DDR | 新建一个持久 backing | 新建 $\tau@k$，连接 `backing → IN → τ@k` |
| $\tau$ 已有 backing | 不创建 | 复用已有 backing | 新建 $\tau@k$，连接 `backing → IN → τ@k` |
| $\tau$ 由原始 COPY_IN 产生 | 不创建 | 复用原 COPY_IN 的 DDR 输入 | 同上 |

原 logical tensor 在每次换入后得到新的物理 incarnation：$\tau@0,\tau@1,\ldots$。两次 spill 边界之间的全部 consumer 边都重连到对应 incarnation。Step3 因而可直接以 tensor fan-out 建立引用计数，不需要额外驻留段表。

### 2.4 算法

**首先, tensor 涉及序列与生命周期预计算**：

1. 遍历 graph_json 二部图，对每个非 DDR tensor $\tau$：
   - 收集 $\tau$ 涉及的所有 op（生产者 + 所有消费者）
   - 按 op 在 $\text{seq}$ 中的 step 排序，得 $\text{uses}(\tau) = [(\text{step}_1, \text{op}_1), \ldots]$
   - 记录 $\text{first}(\tau) = \text{step}_1$, $\text{last}(\tau) = \text{step}_k$, $\text{pos}(\tau)$, $\text{size}(\tau)$
2. 初始化：$\text{cur\_use\_idx}[\tau] = 0$（指向 $\text{uses}(\tau)$ 的下一项）, $\text{active}[T] = \varnothing$
3. 复杂度 $O(|V| + |E|)$，与步骤 1 的"首先"阶段同阶。

**然后, 顺序遍历模拟 + Belady 选 victim**：

按 $\text{seq}$ 顺序遍历 $t = 0, 1, \ldots, |\text{seq}|-1$。每步严格执行五段动作：

**(a0) 处理 scheduled COPY_IN**（**必须在 (a) 之前**）：

对每个已触发的 SPILL，其 $\text{in\_before\_step} = t$ 时, 把对应的 victim $\tau$ 重新加入 $\text{active}[\text{pos}(\tau)]$（等价于物理上 COPY_IN 把 $\tau$ 从 DDR 装回片上）。设 victim 在 $\text{uses}(\tau)$ 中当前 use 索引为 $u$（即 $\text{uses}(\tau)[u].\text{step} = t$），新条目记 $(\text{uses}(\tau)[u+1].\text{step},\ u,\ \tau)$。

> **为什么必须在 (a) 之前**：(a) 的中间 use 分支只**更新已存在项**，不**新增**。若先把 victim 移出 active 再走到 (a)，中间 use 在 active 中找不到该 tensor，这一步的 next_use 就不会被推进。因此必须先在 (a0) 把 victim 加回 active，再由 (a) 正常更新 next_use。

> **与首次 use 分支不重复**：(a0) 写入的 `u` 与 (a) 写入的 `u+1` 相差 1：进入 (a0) 时 cur_use_idx 尚未递增，victim 已处理的 use 数为 $u$（uses[0..u-1]）；(a) 处理完 uses[u] 后变为 $u+1$。两者都表示"事件触发瞬间的已发生数"。

**(a) 处理本步 use 的 alloc / next_use，延迟 last-use free**：对每个 $\tau$ 满足 $\text{uses}(\tau)[\text{cur\_use\_idx}[\tau]].step = t$：

- $\text{cur\_use\_idx}[\tau] = 0$（生产）：把 $\tau$ 加入 $\text{active}[\text{pos}(\tau)]$，其 $\text{next\_use} = \text{uses}(\tau)[1].step$（若 $k \ge 2$），否则 $\varnothing$；即使 $k=1$ 也先加入以计入本 op 的 alloc 峰值
- $0 < \text{cur\_use\_idx}[\tau] < k-1$（中间 use）：更新 active 中 $\tau$ 的 $\text{next\_use}$ 为 $\text{uses}(\tau)[\text{cur\_use\_idx}+1].step$
- $\text{cur\_use\_idx}[\tau] = k-1$（最后一次 use）：加入 `release_after_execute`，此时仍保留在 active
- $\text{cur\_use\_idx}[\tau] \gets \text{cur\_use\_idx}[\tau] + 1$

**(b) 检测每 Type 溢出**（独立 per Type）：

此时 COPY_IN、当前输入和输出均驻留，且末次输入尚未 free。若 $\text{resid}^{alloc}_T(t) > C_T$，记入 $\text{overflow\_log}$，进入 **(c)** 循环直至 $\text{resid}^{alloc}_T(t) \le C_T$。

**(c) Belady 选 victim + 触发 SPILL**：

```
victim_pool[T] = { (next_use, used_count, tid) ∈ active[T]
                   | next_use ≠ ∅ and tid 不属于当前 op 的输入/输出 }
if victim_pool[T] is empty:
    # 正常输入约束下不可达；禁止清空 active 掩盖错误
    print step/op/type/resid/capacity/current_tids/active 到 stderr 和 case 日志
    raise Step2SchedulingError
v = argmax_{v ∈ victim_pool[T]} v.next_use      # Belady
prev_use_step = uses(v.tid)[v.used_count - 1].step
next_use_step = v.next_use
prev_use_op   = uses(v.tid)[v.used_count - 1].op
next_use_op   = uses(v.tid)[v.used_count    ].op
# 从 active[T] 移除 (v.tid 不再占 T 容量, 数据在 DDR)
active[T] = active[T] \ {v}
# 记录 SPILL spec
pending_spills.append({
    'out_after_step': prev_use_step,
    'in_before_step': next_use_step,
    'tid': v.tid, 'pos': T, 'size': size(v.tid),
    'prev_use_op': prev_use_op, 'next_use_op': next_use_op,
})
# 回到 (b) 重新检查
```

**(d) 后置容量断言**：SPILL 循环结束后断言 $\text{resid}^{alloc}_T(t) \le C_T$。若失败，打印 step/op/type/resid/capacity 并抛出 `Step2SchedulingError`。

**(e) execute + last-use free**：当前 op 执行完成后，统一从 active 移除 `release_after_execute` 中的 tensor，得到 $\text{Active}^{steady}_T(t)$。

**关键性质**：

- 选 victim 时只看 $\text{next\_use} \neq \varnothing$ 且不属于当前 op 输入/输出的活跃 tensor，保证写回 DDR 的动作不会破坏当前 op
- 找不到 victim 是硬错误而不是可恢复状态；在“单个 op 的全部当前驻留量不超过容量”前提下理论上不可达，因此作为实现/输入约束拦截
- Belady 单 cache 最优：换出"未来最久不用"的，让它最迟回来

**最后, 扩展序列生成**：

1. 每个 pending spill 始终分配 COPY_IN id 和新的片上 tensor id；仅在尚无 backing 时分配真实 COPY_OUT 与 DDR backing id。
2. 建立 `backing → COPY_IN → renamed_tensor`；真实 COPY_OUT 建立 `old_incarnation → COPY_OUT → backing`。
3. 将下一次换入至下一个 spill 边界之间的全部 consumer 边，从 logical tensor 重连到 renamed tensor。
4. 构建 $\text{seq}_{\text{ext}}$：COPY_IN 插在下一次 use 前；只有真实 COPY_OUT 插在对应位置。

$$
\text{seq}_{\text{ext}}[i] = \begin{cases}
\text{insert\_after}[i-1] \circ \text{insert\_before}[i] \circ \text{seq}[i] & i = 0 \\
\text{insert\_before}[i] \circ \text{seq}[i] \circ \text{insert\_after}[i] & 0 < i < n \\
\text{insert\_before}[n-1] \circ \text{seq}[n-1] \circ \text{insert\_after}[n-1] & i = n-1
\end{cases}
$$

其中 $\text{insert\_after}[s]$ = 在 $\text{seq}[s]$ 之后插入的 `COPY_OUT` 节点列表（同一位置多个时按生成顺序），$\text{insert\_before}[s]$ = 在 $\text{seq}[s]$ 之前插入的 `COPY_IN` 节点列表。

> 已有 backing 时该位置只有 COPY_IN；上一 incarnation 的释放由 Step3 在其全部 consumer 完成后自动完成。

### 2.5 伪代码

```python
def step2_spill_insertion(graph_json, seq, capacity):
    # capacity 由调用方从 config.txt 的 [capacity] 段读出后传入, 此处不再兜底

    # ---- 2.4 首先: 预计算 ----
    tensor_uses, op_step, _ = _build_tensor_uses(graph_json, seq)
    tensor_lifecycle = {}
    for t in graph_json['tensors']:
        if t['pos'] == 'DDR' or t['id'] not in tensor_uses:
            continue
        uses = tensor_uses[t['id']]
        tensor_lifecycle[t['id']] = {
            'pos': t['pos'], 'size': t['size'], 'uses': uses,
            'first': uses[0][0], 'last': uses[-1][0],
        }

    max_id = max(o['id'] for o in graph_json['ops'])
    max_tid = max((t['id'] for t in graph_json['tensors']), default=0)
    next_id = max(max_id, max_tid) + 1

    # ---- 2.4 然后: 顺序遍历 + Belady ----
    active = {T: [] for T in capacity}      # list of (next_use, used_count, tid)
    cur_use_idx = {tid: 0 for tid in tensor_lifecycle}
    pending_spills = []
    overflow_log = []

    def get_resid(T):
        return sum(tensor_lifecycle[t2]['size'] for (_, _, t2) in active[T])

    for t in range(len(seq)):
        # (a0) scheduled COPY_IN: 把 SPILL 出去的 victim 重新 alloc 回片上
        #     必须在 (a) 之前, 否则 (a) 中间 use 分支找不到 victim, next_use 无法推进
        for sp in pending_spills:
            if sp['in_before_step'] != t:
                continue
            tid = sp['tid']
            if tid not in tensor_lifecycle:   # DDR swap 不参与
                continue
            T = tensor_lifecycle[tid]['pos']
            uses = tensor_lifecycle[tid]['uses']
            for u, (s, _) in enumerate(uses):
                if s != t:
                    continue
                # uses[u] 是 victim 在 step t 的中间 use (SPILL 把它换出后又通过
                # COPY_IN 接回来). 此时 victim 不应已在 active (换出时已移除).
                new_nu = uses[u + 1][0] if u + 1 < len(uses) else None
                if not any(t2 == tid for (_, _, t2) in active[T]):
                    active[T].append((new_nu, u, tid))   # ui = u (cur_use_idx 还没 +1)
                break

        # (a) alloc / 更新 next_use；last-use free 延迟到容量检查之后
        release_after_execute = []
        for tid, info in tensor_lifecycle.items():
            uses = info['uses']
            idx = cur_use_idx[tid]
            if idx < len(uses) and uses[idx][0] == t:
                T = info['pos']
                if idx == 0:           # 生产
                    next_nu = uses[1][0] if 1 < len(uses) else None
                    active[T].append((next_nu, 1, tid))
                elif idx < len(uses) - 1:    # 中间 use, 更新 next_use
                    new_nu = uses[idx + 1][0] if idx + 1 < len(uses) else None
                    for j, (nu, ui, t2) in enumerate(active[T]):
                        if t2 == tid:
                            active[T][j] = (new_nu, ui + 1, tid)
                            break
                if idx == len(uses) - 1:
                    release_after_execute.append((T, tid))
                cur_use_idx[tid] = idx + 1

        # (b) alloc 后、execute/free 前检测 + (c) Belady SPILL
        for T, C in capacity.items():
            resid = get_resid(T)
            while resid > C:
                overflow_log.append({'step': t, 'type': T, 'resid': resid, 'capacity': C})
                finite = [(nu, ui, tid) for (nu, ui, tid) in active[T]
                          if nu is not None
                          and not any(s == t for s, _ in tensor_lifecycle[tid]['uses'])]
                if not finite:
                    print_error_context_to_stderr_and_case_log(...)
                    raise Step2SchedulingError(...)
                nu, ui, victim_tid = max(finite, key=lambda x: x[0])
                info = tensor_lifecycle[victim_tid]
                active[T] = [(nu2, ui2, t2) for (nu2, ui2, t2) in active[T]
                             if t2 != victim_tid]
                pending_spills.append({
                    'out_after_step': info['uses'][ui - 1][0],
                    'in_before_step': nu,
                    'tid': victim_tid, 'pos': T, 'size': info['size'],
                    'prev_use_op': info['uses'][ui - 1][1],
                    'next_use_op': info['uses'][ui][1],
                })
                resid = get_resid(T)
            assert resid <= C

        # (e) execute 完成后才释放末次 use tensor
        for T, tid in release_after_execute:
            active[T] = [(nu, ui, t2) for (nu, ui, t2) in active[T] if t2 != tid]
    
    # ---- 2.4 最后: 扩展序列生成 ----
    new_ops_list, new_tensors_list, new_edges, spill_records = [], [], [], []
    insert_after = defaultdict(list)   # pos -> [spill_out_id]
    insert_before = defaultdict(list)  # pos -> [spill_in_id]
    
    backing_by_tid = find_original_copy_in_backings(graph_json)
    current_incarnation = {tid: tid for tid in tensor_lifecycle}
    for sp in pending_spills:
        si_id = next_id; next_id += 1
        copies_data = sp['tid'] not in backing_by_tid
        from_tid = current_incarnation[sp['tid']]
        if copies_data:
            so_id = next_id; next_id += 1
            backing_tid = next_id; next_id += 1
            backing_by_tid[sp['tid']] = backing_tid
            new_tensors_list.append({'id': backing_tid, 'pos': 'DDR', 'size': sp['size']})
        else:
            so_id = None
            backing_tid = backing_by_tid[sp['tid']]
        to_tid = next_id; next_id += 1
        current_incarnation[sp['tid']] = to_tid
        new_tensors_list.append({
            'id': to_tid, 'logical_tid': sp['tid'], 'version': next_version(sp['tid']),
            'pos': sp['pos'], 'size': sp['size']})
        if copies_data:
            new_ops_list.append({'id': so_id, 'op': 'COPY_OUT', 'pipe': 'PIPE_MTE3',
                                 'cycles': max(1, sp['size'] // 64)})
        new_ops_list.append({'id': si_id, 'op': 'COPY_IN', 'pipe': 'PIPE_MTE2',
                             'cycles': max(1, sp['size'] // 64)})
        if copies_data:
            new_edges.append((from_tid, so_id))
            new_edges.append((so_id, backing_tid))
        new_edges.append((backing_tid, si_id))
        new_edges.append((si_id, to_tid))
        if copies_data:
            insert_after[sp['out_after_step']].append(so_id)
        insert_before[sp['in_before_step']].append(si_id)
        spill_records.append({
            'spill_out_id': so_id, 'spill_in_id': si_id,
            'backing_tid': backing_tid,
            'spill_out_copies_data': copies_data,
            'from_tid': from_tid, 'to_tid': to_tid,
            'tid': sp['tid'], 'pos': sp['pos'], 'size': sp['size'],
            'prev_use_op': sp['prev_use_op'], 'next_use_op': sp['next_use_op'],
            'prev_use_step': sp['out_after_step'], 'next_use_step': sp['in_before_step'],
        })

    # 对每条 logical_tid -> consumer 边，按 consumer 的 seq step 选择对应
    # incarnation，并把边改接为 incarnation_tid -> consumer。
    ext_edges = rewire_all_consumers(graph_json.edges, spill_records) + new_edges
    
    seq_ext = []
    for i, op in enumerate(seq):
        if i > 0:
            for sid in insert_after[i - 1]: seq_ext.append(sid)
        for sid in insert_before[i]: seq_ext.append(sid)
        seq_ext.append(op)
    for sid in insert_after[len(seq) - 1]: seq_ext.append(sid)
    
    return {
        'seq_ext': seq_ext, 'spill_records': spill_records,
        'new_edges': new_edges, 'removed_edges': removed_edges,
        'ext_edges': ext_edges, 'new_ops': new_ops_list,
        'new_tensors': new_tensors_list,
        'overflow_log': overflow_log, 'capacity': capacity,
    }
```

### 2.6 边界条件

| 场景 | 处理 |
|------|------|
| $k = 1$（$\tau$ 仅一个 use，生产即消费） | 先 alloc 并计入当前 op 瞬态峰值，execute 后立即 free；它属于当前 op，不能被选作 victim |
| $k = 0$（无 use 的孤立 tensor） | 预计算时跳过，不进入 active，不参与 SPILL |
| $\tau$ 的 $\text{next\_use} = \varnothing$ | 选 victim 时跳过；若容量仍超限且无其他合法 victim，打印错误上下文并抛出 `Step2SchedulingError`，绝不清空 active |
| victim 的 $\text{size}$ 超过 $C_T$ | 单 tensor 装不下；本算法不会选中（逻辑上 victim 必须在 $\text{active}[T]$，意味着它原本就装得下） |
| 多 Type 同时溢出 | 每 Type 独立循环（2.4 然后 b/c 段在 for T 循环内） |
| 同一 Type 多个 tensor 同时溢出 | 反复 while 直至 $\text{resid}_T \le C_T$ |
| 同一 tensor 多次被选 victim | 每次新建 COPY_IN 和 renamed tensor；只有第一次真实写回 DDR 并建 backing |
| tensor 由 COPY_IN 从 DDR 产生 | 复用原 DDR 输入作为 backing；不新增写回 DDR 的 COPY_OUT |
| 位置 $i$ 既有 $\text{insert\_after}[i-1]$ 又有 $\text{insert\_before}[i]$ | $\text{seq}_{\text{ext}}$ 顺序：$\text{insert\_after}[i-1]$ → $\text{insert\_before}[i]$ → $\text{seq}[i]$ |
| 多个 COPY_OUT 同位置 | 按生成顺序串行；不依赖彼此，可并行 |
| $\text{seq}[i-1]$ 后无 SPILL 且 $\text{seq}[i]$ 前无 SPILL | $\text{seq}_{\text{ext}}$ 元素 = $\text{seq}[i]$，无变化 |
| $k$ 中 $\text{step}$ 间隔极大 | SPILL 跨越大量原 op；COPY_IN 仍插在 $\text{step}_{i+1}$ 对应 op 之前 |

### 2.7 复杂度

- 预计算 use 序列：$O(|V| + |E|)$（每条二部图边贡献一次 use 记录，排序后 $O(|V| \log |V|)$）
- 主循环：每步 $O(\log R)$（找 victim 是 max over list，$O(R)$；$R$ = active size，最坏 $O(|V|)$）。整体 $O(|V|^2)$ 最坏，可改堆到 $O(|V| \log |V|)$
- **(a0) 扫描 scheduled COPY_IN**：每步 $O(S)$（$S$ = pending_spills 总数），最坏 $|V|$。由于 $\sum_t (\text{(a0) 命中数}) = O(S)$，总代价 $O(S)$ 平摊到 $|V|$ 步 = 每步 $O(S/|V|)$ 期望
- SPILL 次数：最坏 $O(|V|)$（每个 tensor 都被换出再换回）
- 总时间：$O(|V|^2 + S)$（当前实现）/ $O(|V| \log |V| + S)$（堆优化后）
- 总空间：$O(|V| + S)$

### 2.8 实测验证（4 个 case，capacity L1=524288, UB=131072）

| Case | $\|V\|$ | $\#\text{edges}$ | SPILL 数 | $\text{peak}_{L1}$ | L1 占比 | $\text{peak}_{UB}$ | UB 占比 |
|------|------|------|------|------|------|------|------|
| small\_50  | 43  | 110  | 0  | 352000  | 67.1%  | 50247   | 38.3%  |
| medium\_100 | 88  | 239  | 4  | 492000  | 93.8%  | 56232   | 42.9%  |
| medium\_150 | 131 | 376  | 7  | 516018  | **98.4%**  | 118049  | 90.1%  |
| large\_200  | 186 | 530  | 16 | 510475  | **97.4%**  | 127680  | **97.4%**  |

4 个 case 按最终 $\text{seq}_{ext}$ 独立复演，全部 alloc 后 L1/UB 峰值 $\le$ 容量（$\le 100\%$）。其中 medium\_100 的 alloc 后 L1 峰值为 492000：若不把末次输入的释放推迟到容量检查之后，该峰值会只被统计到 452640，从而漏报执行 `op#43` 前应额外换出的 t10064（out\_after=29, in\_before=56）。

large\_200 最终 alloc 峰值 L1=510475、UB=127680，均与扩展序列独立复演一致。

## 3. 步骤 3：乱序流水排布

> **接口**：`step3_simulation(ext_graph, capacity, bandwidth)`。容量与带宽由调用方从 `config.txt` 读出后传入，本步骤不内置默认值。

### 3.1 输入、目标与输出

输入：

- Step2 产生的扩展图 `ext_graph = {ops, tensors, edges, seq_ext}`
- 4 类 Pipe 的执行器数量固定为每条 Pipe 1 个（硬件约束，不可配置）
- DDR 带宽参数 `bandwidth`（来自 `config.txt` 的 `[bandwidth]`，评测配置为 60 字节/周期）；本步骤据此计算单个 DDR COPY 独占带宽时的参考时长
- 每类片上内存容量 `capacity`（来自 `config.txt` 的 `[capacity]`）

目标：在满足全部图依赖和 Pipe 互斥的前提下，尽早发射 op，输出：

- `makespan`
- `op_start[op_id]`、`op_end[op_id]`
- `per_pipe_timeline[pipe]`、`pipe_orders[pipe]`
- `op_status` 与 `pred_remaining`（成功返回时所有 op 均为 done）
- `memory_peak`、`memory_events`、`memory_used_final`
- `execution_graph`（补齐内存复用依赖后的执行图）与 `memory_dependencies`

Step3 不返回部分调度结果。若卡死，直接进入 3.5 的失败路径。

### 3.2 统一依赖构建

Step3 只解释图结构，不识别节点来源：

1. 对 `op → tensor → op` 路径建立 producer 到 consumer 的依赖。
2. 对直接 `op → op` 边原样建立依赖。
3. DDR tensor 同样参与数据依赖和 COPY 时长计算，但不建立任何内存状态。
4. Step2 新增的 COPY_IN/COPY_OUT 节点与原始 op 一样进入依赖图和 Pipe 队列。
5. 每个 op 归属哪条 Pipe 直接取该 op 自身的 `pipe` 字段，不按 `op` 名称推断。

每个重命名 tensor 节点就是一段物理驻留生命周期；Step3 无需另建驻留段表。

### 3.3 调度算法

**前置约定**（由 Step2 的输出保证，Step3 不重复校验）：

- `seq_ext` 长度等于 op 数，且是全部 op 的一个排列；
- `ext_graph` 为无环图，所有片上 tensor 的容量需求可被 `capacity` 容纳。

**然后，初始化**：

- 构建 `preds/succs` 与 `pred_remaining`；
- 为每个片上 tensor 建立 producer、consumer 集合与 `remaining_consumers`；
- 无 producer 的片上输入在 $t=0$ 预分配；
- 所有产生片上输出的 op 构成 allocation order，顺序与 `seq_ext` 一致。

**主循环每轮三段**：

1. **retire**：op 完成后递减其所有输入 tensor 的引用计数；归零立即 free，并递减后继依赖。
2. **issue**：片上输出 allocation 必须轮到 allocation order 且 `used + required ≤ capacity`；成功后先 alloc 再发射。无片上输出的 op 可绕过被容量阻塞的 allocation op。DDR COPY 在核内阶段只记录独占带宽时的参考工作量。
3. **advance**：跳到所有运行中 op 的最早结束时间。

全部 op done 且各类 `memory_used_final = 0` 后成功结束。Step3 含内存申请、释放和容量等待，但不含 victim 选择或二次换出。

### 3.4 与多核模拟的接口

核内步骤输出扩展图、确定性操作顺序、每个 COPY 的数据量及其独占带宽参考工作量，不在单个 Task 内决定跨核完成时间。多核评估器将各 Task 的操作装入对应核心的 Pipe 队列，并统一处理跨核依赖、DDR/Cache 共享带宽和最终时间推进。具体规则见[《多核并行模拟执行算法》](多核并行模拟执行算法.md)。

### 3.5 卡死拦截与错误日志

以下任一情况都判为调度失败，不返回部分结果：

- 尚有未完成 op，但所有 issue queue 和 executor 都为空（`scheduler deadlock`）；
- 迭代次数超过 `max_iter`；
- op 的 `pipe` 字段不在四条 Pipe 之内（`missing pipe capacity`）；
- 虚拟容量额度在释放依赖上出现缺口（`virtual capacity credits exhausted`）；
- 初始驻留 tensor 已超出容量（`initial resident tensors exceed capacity`）；
- 输出契约检查失败：Pipe 顺序未覆盖全部 op 恰好一次，或内存复用依赖成环。

失败时：

1. 向 stderr 打印以 `[STEP3 ERROR]` 开头的诊断；
2. 抛出 `Step3SchedulingError`，不返回部分结果；
3. 评估入口捕获后向 stderr 打印 `[EVALUATION ERROR]` 并以非零退出码结束，不写出该算例的结果 JSON 与 Trace；已写入的日志文件不包含成功结果；
4. 死锁诊断至少包含 reason、time、iteration、状态计数、每条 Pipe 的 queue/executor，以及每个未完成 op 的：
   - op id / type / pipe / seq_pos / status
   - `pred_remaining`
   - `unresolved_preds`
   - `in_tids/out_tids`

在 Step2 严格保证内存、扩展图无环且 Pipe 字段合法的前提下，此失败路径理论上不可达，作为输入和实现错误的拦截门。

### 3.6 COPY 周期与 pipe

| op | pipe | duration |
|---|---|---|
| COPY_IN | PIPE_MTE2 | 优先取输出 tensor 总大小 / bandwidth；无显式输出 tensor 时回退 op.cycles；端点含 DDR 时参与共享 |
| COPY_OUT | PIPE_MTE3 | 优先取输入 tensor 总大小 / bandwidth；无显式输入 tensor 时回退 op.cycles；端点含 DDR 时参与共享 |
| MATMUL/GEMM/CONV | PIPE_M | op.cycles |
| 其余 vector op | PIPE_V | op.cycles |

Step3 日志第二节为每个 `COPY_IN/COPY_OUT` 额外打印：

- `full_bw_duration`：该 COPY 独占相应满带宽时的参考耗时；
- `full_bw_end = start + full_bw_duration`：从实际发射时刻开始且没有带宽抢占时的参考结束时间。

实际的 `end` 和 `duration=end-start` 仍包含 DDR 抢占及最终 cycle 向上取整，可直接与上述参考值比较。

### 3.7 复杂度

- 依赖构建：$O(|V| + |E|)$
- 每个 op 入队、出队一次：$O(|V| \log |V|)$
- retire 与后继唤醒：总计 $O(|E|)$
- 每次 DDR COPY 发射重算在途集合：$O(M\log M)$，$M$ 为同时在途 DDR 搬运数；当前单核 $M\le2$
- 空间：$O(|V| + |E|)$

### 3.8 实测结果

使用上述四个用例经 Step2 得到的扩展图：

| Case | 完成 op | makespan | 卡死 |
|---|---:|---:|---:|
| small_50 | 43/43 | 6815 | 0 |
| medium_100 | 96/96 | 15432 | 0 |
| medium_150 | 145/145 | 21241 | 0 |
| large_200 | 218/218 | 35542 | 0 |

四个 case 均完整结束；makespan 已包含 MTE2/MTE3 同时访问 DDR 时的公平带宽抢占。

### 3.9 配置文件

核内调度使用的两项配置来自 `config.txt`：

```text
[capacity]
L1 524288
UB 131072

[bandwidth]
bandwidth 60
```

`bandwidth` 是 DDR 全局总带宽，用于 DDR COPY 的独占时长与并发平均分配。L1↔UB 内部 COPY 不进入该共享池。`capacity` 由 Step2 与 Step3 共同使用：Step2 用它做溢出检测与 SPILL 插入，Step3 用它做片上 tensor 的分配门控与峰值统计。

本算法不读取 `config.txt` 的其余段落；题目 1/2/3 各自的等待周期与题目 3 的 Cache 参数由多核评估器读取，见[《多核并行模拟执行算法》](多核并行模拟执行算法.md)。

## 4. 端到端示例

为便于核对三步算法，本节用一个**微型 4-op 图**手动推演。

### 4.1 输入

```
ops:  1 (COPY_IN T1, PIPE_MTE2, 15cyc)
      2 (MATMUL a=T1, b=T2 → T3, PIPE_M, 200cyc)
      3 (RELU T3 → T4, PIPE_V, 30cyc)
      4 (COPY_OUT T4, PIPE_MTE3, 15cyc)
tensors: T1(DDR, 100), T2(DDR, 100), T3(L1, 100), T4(UB, 100)
edges: {1 → T1}, {T1 → 2}         (op 1 产 T1, 供 op 2)
       {T2 → 2}                   (T2 已存在于 DDR, 无内部 producer)
       {2 → T3}, {T3 → 3}         (op 2 产 T3, 供 op 3)
       {3 → T4}, {T4 → 4}         (op 3 产 T4, 供 op 4)
```

### 4.2 步骤 1：反向 DFS 拓扑

out 节点 = {4}。栈模拟：

```
栈: [4]                     → 4 前驱 3 未访问, 压 3: [3, 4]
栈: [3, 4]                  → 3 前驱 2 未访问, 压 2: [2, 3, 4]
栈: [2, 3, 4]               → 2 前驱 1 未访问, 压 1: [1, 2, 3, 4]
栈: [1, 2, 3, 4]            → 1 无前驱, 弹出访问: seq = [1]
栈: [2, 3, 4]               → 2 前驱 (1) 都访问, 弹出: seq = [1, 2]
栈: [3, 4]                  → 3 前驱 (2) 都访问, 弹出: seq = [1, 2, 3]
栈: [4]                     → 4 前驱 (3) 都访问, 弹出: seq = [1, 2, 3, 4]
```

输出访问顺序：`seq = [op1, op2, op3, op4]`

### 4.3 步骤 2：缓存换入换出

**2.4.1 生命周期扫描**：

| tensor | 第一次出现 (first) | 最后一次出现 (last) | Type |
|--------|-------------------|-------------------|------|
| T1 | 0 (op1, COPY_IN) | 1 (op2 输入) | DDR (不占 L1/UB) |
| T2 | 1 (op2 输入) | 1 (op2 输入) | DDR |
| T3 | 1 (op2 输出) | 2 (op3 输入) | L1 |
| T4 | 2 (op3 输出) | 3 (op4 输入) | UB |

DDR 类型不计入 L1/UB 容量，算法只跟踪 L1/UB 类的驻留量。

**2.4.2 顺序遍历**（按 `config.txt`：L1=524288，UB=131072；本图 tensor 很小，远离容量上限）：

```
t=0 (op1): 涉及 T1 (DDR) — 不影响 L1/UB 驻留
t=1 (op2): 涉及 T2 (DDR, 瞬时), T1 (DDR, 释放)
            涉及 T3 (L1): 申请 +100 → L1 驻留 = 100
t=2 (op3): 涉及 T3 (L1, 释放) → L1 驻留 = 0
            涉及 T4 (UB): 申请 +100 → UB 驻留 = 100
t=3 (op4): 涉及 T4 (UB, 释放) → UB 驻留 = 0
```

**无溢出**，不需要 SPILL。SPILL 记录 = 空。

### 4.4 步骤 3：流水排布

```
FIFO per pipe:
  PIPE_MTE2: op1 (0..15)
  PIPE_M:    op2 (15..215)  # 等 op1 完成 (pred_end=15) 且 MTE2 队列空 (15)
  PIPE_V:    op3 (215..245) # 等 op2 完成 (215)
  PIPE_MTE3: op4 (245..260) # 等 op3 完成 (245)
```

总执行时间 = 260 cycles。

### 4.5 溢出与换出判定

在上例基础上增大 tensor 尺寸即可触发换出。判定过程遵循 2.4 的 (b)(c) 两步，要点有三条：

1. **溢出门限**：某一步在 alloc 完成后、execute/free 之前，若 $\text{resid}^{alloc}_T(t) > C_T$，记入 `overflow_log` 并进入换出循环，直到驻留量回到容量以内。
2. **victim 必须"当前不被使用"**：候选集合排除所有在 step $t$ 被使用的 tensor（即 `uses` 中包含 step $t$ 的项）。否则换出节点只能排在该 op 之后，op 自身仍会瞬时超容量。
3. **victim 必须"还有后续 use"**：$\text{next\_use} = \varnothing$ 的 tensor 会被跳过（它即将释放，换出没有意义）。候选之间按 $\text{next\_use}$ 最大者优先，即 Belady 准则——换出未来最久才用到的那个。

若候选集合为空（例如当前 op 的全部输入输出之和已超过容量，或没有"还有后续 use"的 tensor），算法不静默清空 active，而是打印 step/op/type/resid/capacity/current_tids/active 上下文并抛出 `Step2SchedulingError`，由评估入口转为 `[EVALUATION ERROR]` 退出。

换出成功后，该 tensor 的记录形如：

```
{ tid, size, prev_use_step, next_use_step, prev_use_op, next_use_op,
  spill_out_id, spill_in_id, spill_out_copies_data, from_tid, to_tid, backing_tid }
```

- `prev_use_step` / `next_use_step`：换出排在 `prev_use_step` 对应 op 之后，换入排在 `next_use_step` 对应 op 之前；
- `spill_out_copies_data = true` 表示这是该 tensor 首次写回 DDR，会同时产生 `COPY_OUT` 与 `COPY_IN` 两个节点以及一个持久 backing；为 `false` 时复用已有 backing，只产生 `COPY_IN`。

### 4.6 输出

沿用 4.4 的 $260$ cycles 结果；若上例发生一次换出（T3 首次写回），扩展序列与换出记录形如：

```
调度序列: [op1, op2, op3, COPY_OUT(T3), ..., COPY_IN(T3), op5, ...]
换出记录: [
  { tid: T3, size, prev_use_step, next_use_step,
    spill_out_copies_data: true, spill_out_id, spill_in_id, backing_tid },
]
时间表:   (由步骤 3 给出)
```

## 5. 算法性质总结

| 性质 | 描述 |
|------|------|
| **确定性** | 三步全部确定性，相同输入必得相同输出（无随机、无学习、无外部参数） |
| **拓扑正确** | 步骤 1 严格保证拓扑序；步骤 2 插入 SPILL 时按"前驱后继" 加边，不破坏原拓扑 |
| **容量满足** | 步骤 2 在每种 Type 上独立做溢出检测，输出扩展图每种 Type 驻留量 ≤ 容量 |
| **SPILL 最小化（单 cache）** | 步骤 2 选 victim 用 Belady 准则，对单 cache 最优；多 cache 独立处理是近似 |
| **不分配地址** | 步骤 2 只跟踪占用量，不输出 Offset；Offset 由赛题原题问题 2 的"缓存分配" 步骤在扩展图上独立完成 |
| **可作为真值** | 三步总时间复杂度 $O(|V| \log |V| + S)$，对 4 万节点级（Conv_Case1）可在毫秒级跑完 |
