# 多核并行模拟执行算法

> **适用范围**：《通用神经网络处理器下的多核调度问题》问题 1—3
> **输入**：原始计算图、参赛者提交的多核方案 `node_to_subgraph`/`core_schedules` 和 `config.txt`
> **输出**：全局 Makespan、各核 Task/子图/操作时间线、核内存储峰值、数据搬运量，以及问题 3 的 Cache 统计
> **职责边界**：单个 Task 的拓扑排序、缓存换入换出插入和核内操作顺序见[《核内调度算法》](核内调度算法.md)。本文只描述多个核心、Task 和共享资源的并行模拟。

## 1. 总体流程

评估器采用离散事件模拟。它先根据多核方案构造 Task 和跨核依赖，再调用核内调度算法得到每个 Task 的扩展图与确定性操作顺序，最后在统一时间轴上并行推进所有核心：

1. 校验 `node_to_subgraph` 和 `core_schedules`，确定操作所属子图、子图所属核心及同核顺序。
2. 按问题类型构造 Task，并在必要的数据边界插入 `COPY_IN`/`COPY_OUT`。
3. 对每个 Task 执行核内调度，得到扩展图、操作顺序和新增换入换出操作。
4. 初始化每核四条 Pipe、操作状态、核内存储状态、跨核释放事件和共享带宽池。
5. 反复执行“结算完成事件—激活就绪操作—发射操作—推进时间”，直到全部操作完成。
6. 汇总全局 Makespan、时间线、存储峰值、搬运量及 Cache 统计；若状态无法推进，则直接报错。

## 2. Task 构造

### 2.1 问题 1：每个子图一个 Task

每个子图独立构成一个 Task，并按照 `core_schedules` 分配到核心。同一核心同一时刻只激活一个 Task，激活顺序严格遵循该核心的子图列表。

Task 内使用私有 L1/UB。凡是从 Task 外部输入的数据，都在 Task 边界插入一对 DDR 张量和 `COPY_IN`；凡是输出到其他 Task 或原图最终输出的数据，都插入 DDR 张量和 `COPY_OUT`。因此，即使相邻子图位于同一核心，它们也不跨 Task 保留片上数据。

一个 Task 只有在以下条件全部满足时才能激活：

- 其所有前驱 Task 已完成；
- 该核心的前一个 Task 已完成；
- 同核前序 Task 完成后至少等待 `task_same_core_wait_cycles`；
- 跨核前驱 Task 完成后至少等待 `task_cross_core_wait_cycles`。

两项等待周期取自 `config.txt` 的 `[multicore_scene_a]` 段，评测配置为 100 与 1000 cycles，代码中不设默认值。

### 2.2 问题 2、3：每个核心一个合并 Task

同一核心上的全部子图合并为一个 Task，并保留 `core_schedules` 指定的子图顺序。仅跨核数据边插入源核 `COPY_OUT` 和目标核 `COPY_IN`；同核相邻子图直接保留片上数据及原始依赖。

跨核传输的目标 `COPY_IN` 需等待源 `COPY_OUT` 完成，并额外等待 `cross_core_copy_delay_cycles`（取自 `config.txt` 的 `[multicore_scene_b]` 段，评测配置为 500 cycles）。该延迟只决定目标操作的最早释放时刻，不占用 Pipe 或带宽池。

## 3. 核内操作状态与资源

每个操作依次处于 `pending`、`ready`、`running` 和 `done` 状态。评估器为每个核心分别维护 `PIPE_MTE2`、`PIPE_MTE3`、`PIPE_M` 和 `PIPE_V` 的就绪队列与执行器；同一核心的同一 Pipe 同时最多执行一个操作，不同核心或不同 Pipe 可以并行。

操作进入就绪队列需同时满足：

- Task 已激活；
- 所有核内前驱已完成；
- 所有跨核前驱已完成，且附加同步延迟已到期；
- 若操作产生片上张量，其申请顺序轮到该操作，且 L1/UB 剩余容量足够。

就绪队列按核内调度给出的确定性顺序排序。操作发射前申请输出张量；操作完成后递减输入张量的剩余引用计数，最后一个使用者完成时立即释放对应片上空间。若 Task 结束后仍有片上张量驻留，则判定模拟状态错误。

## 4. 共享 DDR 带宽

`COPY_IN` 固定使用 `PIPE_MTE2`，`COPY_OUT` 固定使用 `PIPE_MTE3`。COPY 的任一端位于 DDR 时，视为 DDR 搬运；L1 与 UB 之间的片上 COPY 只占对应 Pipe，不进入 DDR 带宽池。

所有核心正在执行的 DDR 搬运共享同一个总带宽池，总带宽 `bandwidth` 取自 `config.txt` 的 `[bandwidth]` 段（评测配置为 60 字节/周期）。对每个在途搬运维护 `remaining_work`，其单位是该搬运独占全部 DDR 带宽时尚需的 cycle。若当前有 (n) 个在途搬运，则在经过 Δt 后，每个搬运减少的工作量为：

$$
\Delta w=\frac{\Delta t}{n}.
$$

每当新搬运加入或已有搬运完成时，先按旧并发数结算截至当前时刻的工作量，再重算所有在途搬运的预计结束时间。将剩余工作量排序为 (w_1\le\cdots\le w_n)，令 (w_0=0)，第 (i) 层工作量消耗的真实时间为：

$$
\Delta t_i=(w_i-w_{i-1})(n-i+1).
$$

逐层累加即可得到每个搬运的预计结束时刻；最终时间戳向上取整到整数 cycle。若多个搬运的剩余工作量相同，则它们在同一时刻完成，并同时从带宽池移除。该计算保证任一时段内所有活跃搬运公平共享总带宽，且已完成搬运不会因整数取整继续占用带宽。

## 5. 问题 3 的 FIFO Cache

问题 3 在 DDR 之外增加只读 Cache。Cache 以逻辑 tensor id 为键，使用 FIFO 顺序记录驻留项；命中不会刷新其先后顺序。

- 只有 `COPY_IN` 可以查询并命中 Cache。
- 未命中：操作进入 DDR 带宽池，完成后按 FIFO 规则写入 Cache。
- 命中：操作与 DDR 访问隔离，不进入 DDR 带宽池，而是进入共享 `CACHE_READ` 带宽池。
- 容量不足：从最早插入的条目开始逐项淘汰，直至新条目可放入；单个 tensor 大于 Cache 总容量时不缓存。

`DDR` 与 `CACHE_READ` 两个带宽池相互独立；每个池内部均按第 4 节的公平共享规则结算。评估器为每次可缓存 COPY_IN 记录命中状态、逻辑 tensor id 和实际访问路径，并汇总访问次数、命中次数、命中字节数、未命中字节数、按字节计算的命中率、FIFO 插入/淘汰事件及最终 Cache 内容。

## 6. 离散事件循环

设当前模拟时刻为 `now`，每轮执行以下步骤：

1. **结算带宽池**：根据 `now-last_update` 更新各在途搬运的 `remaining_work`。
2. **完成操作**：将结束时刻不大于 `now` 的操作标记为 `done`，释放 Pipe，更新核内张量引用与容量，并唤醒核内后继。
3. **处理跨核事件**：源 `COPY_OUT` 完成后，为目标 `COPY_IN` 计算附加延迟结束时刻；到期后将其加入就绪判断。
4. **更新 Cache**：问题 3 中，可缓存 COPY 完成后按 FIFO 规则插入 Cache，并记录插入和淘汰事件。
5. **激活 Task**：问题 1 按每核 Task 顺序和前驱完成时间激活新的 Task；问题 2、3 的每核合并 Task 从时刻 0 开始参与调度。
6. **发射操作**：逐核、逐 Pipe 发射满足依赖、容量和执行器约束的操作；带宽操作加入相应共享池并立即重算预计结束时刻。
7. **推进时间**：取所有运行中操作的预计完成时刻和待处理跨核释放时刻中的最小值作为下一时刻。

伪代码如下：

```text
now = 0
while unfinished_ops > 0:
    settle_bandwidth_pools(now)
    retire_finished_ops(now)
    release_due_cross_core_events(now)
    activate_ready_tasks(now)
    issue_ready_ops(now)

    candidates = running_end_times + pending_release_times
    if candidates is empty:
        fail("deadlock")
    next_now = min(candidates)
    if next_now <= now:
        fail("time does not advance")
    now = next_now
```

## 7. 结束条件与失败检查

全部操作完成后，全局 Makespan 为所有操作结束时刻的最大值。成功结果还必须满足：

- 每个 Task/子图/操作均有完整且一致的起止时间；
- 每核 L1/UB 峰值不超过配置容量，最终占用归零；
- 所有跨核依赖和同核顺序均得到满足；
- 所有带宽池均为空，问题 3 的 Cache 状态与事件记录一致；
- 数据搬运量可拆分为原图 COPY、切图新增 COPY 和核内换入换出新增 COPY。

出现以下任一情况立即失败，不返回部分 Makespan：

- 尚有未完成操作，但不存在运行中操作或待释放事件；
- 下一事件时刻不大于当前时刻；
- 超过最大迭代次数；
- 操作、子图或核心映射不完整，子图依赖成环，或同核顺序违反依赖；
- 核内存储超出容量，或 Task 完成后仍有未释放张量。

## 8. 输出与实现对应

评估器输出结果 JSON、Perfetto Trace JSON 和精简日志。结果 JSON 保存完整数值，Trace 用于查看多核并行时间线，日志用于快速核对配置、Makespan、搬运量、核内存储峰值和 Cache 事件。

当前实现对应以下脚本：

- `singlecore_evaluate.py`：独立单核基准评估，不读取多核方案。
- `multicore_cut_evaluate_problem_1.py`：问题 1，每个子图一个 Task。
- `multicore_cut_evaluate_problem_2.py`：问题 2，每个核心一个合并 Task。
- `multicore_cut_evaluate_problem_3.py`：问题 3，只读 FIFO Cache。

## 9. 配置文件

多核模拟用到的全部参数来自 `config.txt`，代码中不设默认值；缺少必需段或键时评估器直接报错退出。

| 段 | 键 | 用途 | 评测配置 |
|---|---|---|---|
| `[capacity]` | `L1` `UB` | 每核片上容量（字节） | 524288 / 131072 |
| `[bandwidth]` | `bandwidth` | DDR 总带宽（字节/周期） | 60 |
| `[multicore_scene_a]` | `task_cross_core_wait_cycles` `task_same_core_wait_cycles` | 问题 1 的 Task 等待 | 1000 / 100 |
| `[multicore_scene_b]` | `cross_core_copy_delay_cycles` | 问题 2/3 的跨核 COPY 等待 | 500 |
| `[problem_3]` | `cache_capacity_bytes` `cache_bandwidth_bytes_per_cycle` | 问题 3 的 Cache 容量与命中带宽 | 1048576 / 250 |

段名只接受上表五项，出现未知段（例如拼写错误或已废弃的 `[pipe_capacity]`）会报 `unknown section`，不会被静默忽略。`L1`/`UB` 的取值单位是字节，与计算图中 `tensors[].size` 一致。未指定 `--config` 时按"计算图所在目录/config.txt"查找，找不到即报错退出。

## 10. 与成本估算的衔接

核内调度结果可提供每个子图的换入换出搬运量和独占执行参考时间；多核模拟进一步计入 Task 边界、跨核依赖、共享 DDR/Cache 带宽及核心并行性，得到最终 Makespan。若用于训练快速成本预测模型，可将节点数、边数、tensor 大小分布和 Pipe 分布等结构特征作为输入，将新增搬运量和时间惩罚作为监督目标。
